3# The non-socket operations (file, console, process, environment and clock) go
4# through the Microsoft C runtime (msvcrt), which exposes POSIX-compatible
5# functions returning integer file descriptors, so the win32 objects thread them
6# through EO exactly like the posix ones. Sockets stay on Winsock (ws2_32), since
7# the C runtime has no BSD sockets. You can look the functions up in the CRT
8# reference (https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference)
9# and the Winsock reference (https://learn.microsoft.com/en-us/windows/win32/api/winsock2).
