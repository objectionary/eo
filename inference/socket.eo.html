3# To connect to the local server as client you should do:
4#
5# ```
6# socket
7# "127.0.0.1" # localhost IPv4 address
8# 8080 # port
9# .connect
10# [s]
11# s.send "Hello, world" > sent # send message to the socket, `sent` - amount of sent bytes
12# s.recv 12 > buff # receive 12 bytes from the socket, `buff` - received bytes
13# s.as-input.read 5 # make input from socket, `read` attribute is available
14# s.as-output.write "Hi" # make output from socket, `write` attribute is available
15# ```
16#
17# When you dataize `socket.connect`, it creates new socket, connects to the given
18# IP on given port, dataizes provided scope, closes the socket and returns bytes
19# retrieved from scope dataization. On failure at any of the described steps, the fallback of the
20# corresponding operation is returned (or the terminator when it is left unbound).
21#
22# To listen to the incoming connections as server you should do:
23#
24# ```
25# socket
26# "127.0.0.1"
27# 8080
28# .listen
29# [s]
30# s.accept # accept incoming connection on socket,
31# [client] # client is connected client socket
32# client.send "Hi, Jeff" # returns client socket, that has all the attributes
33# client.recv 42 # of the scoped-socket (except "accept" attribute)
34# client.as-input.read 5 # same as in `socket.connect`
35# client.as-output.write "Hi" # same as in `socket.connect`
36# ```
37#
38# When you dataize `socket.listen`, it creates new socket, binds it to the given address and port,
39# starts listening for incoming connections, dataizes provided scope, closes the socket
40# and returns `bytes` retrieved from scope dataization. When `s.accept` is dataized - it dataizes
41# given scope, closes client socket and returns `bytes` retrieved from scope dataization.
42# On failure at any of the described steps, the fallback of the corresponding operation is
43# returned (or the terminator when it is left unbound).
