1# Basic I/O object `console` that allows to
2# interact with operation system console.
3#
4# Imagine, operation system console input is "Hello, world!"
5# Here's how you can use `console` object as input
6# ```
7# seq > @
8# *
9# console # error
10# console.read 4 > c1 # "Hell".as-bytes
11# c1.read 4 > c2 # "o, w".as-bytes
12# console.read 4 > c3 # "orld".as-bytes
13# c2.read 4 > c4 # "!".as-bytes
14# ```
15#
16# Here 16 bytes are read from operation system console.
17# Every `console.read` object returns an input block.
18# Every input block is requested portion of bytes read
19# from console, so it's dataizable.
20# Also every input block has object `read` which allows to get
21# next input block with next portion of bytes read from console
22#
23# Here's how you can write to `console`.
24# ```
25# seq > @
26# *
27# console.write "Hello" > o1
28# o1.write ", " > o2
29# console.write "world!" > o3
30# ```
31#
32# Here `"Hello, world!".as-bytes` bytes are printed to console.
33# The object `write` is an output block.
34# It dataizes the given argument, converts it to string,
35# prints it to the operating system console and returns the next output block
36# ready to `write` again.
37#
38# One implementation does the reading and the writing, and the platform
39# enters it as an adapter carrying the raw syscall object and, for each of
40# the two streams, the name of the call and the descriptor. Each access
41# to the `console` object creates a new console instance, so reusing the
42# returned input/output blocks improves performance by maintaining the
43# same console session:
44#
45# Efficient (recommended):
46# ```
47# console.read 2 > i1
48# i1.read 2 > i2
49# i2.read 2 > i3
50# ```
51#
52# Less efficient (creates new console each time):
53# ```
54# console.read 2 > i1
55# console.read 2 > i2
56# console.read 2 > i3
57# ```
58#
59# Sequential reuse maintains the console state across operations.
