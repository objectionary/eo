1# Object `malloc` is an abstraction of a storage of data in heap
2# memory. The implementation of `malloc` is platform dependent. It may
3# use either OS-level or VM-level memory management mechanism.
4#
5# There are two ways of how `malloc` could be used:
6#
7# First, when the size of the required memory block is known beforehand:
8#
9# ```
10# malloc.of
11# 8
12# [m]
13# m.put 10 > @
14# ```
15#
16# Here, the first argument is a size of allocated block in memory, the second argument
17# is the scope where memory block is available for reading and writing. When `malloc.of` is
18# dataized, it processes the scope, clears the block and returns the result of scope dataization.
19# Therefore, users do not need to manage memory cleanup after allocation.
20#
21# Second, when the size is not known upfront, but there exists
22# an object ready to be dataized and placed into the memory block
23# (the size of the block will be equal to the amount of bytes
24# produced by the dataization of the object):
25#
26# ```
27# malloc.for
28# "Hello world!"
29# [m]
30# m.put "Hello, Jeff!" > @
31# ```
32#
33# Here, the first argument is an object which will be dataized, then a block in memory of given data
34# size is allocated and the data is written to the block. The second argument is the same scope as
35# in the first example.
36#
37# Consider the next code:
38# ```
39# malloc.of
40# 8 # allocate 8 bytes length block in memory
41# [m]
42# seq > @
43# *
44# m.write 2 "Hello" # write object "Hello" with offset 2
45# m.read 3 4 # read 4 bytes from offset 3 -> "ello"
46# m.put 42 # write object 42 with offset 0
47# m.get # just get all the data from the memory block -> 42
48# m.size # get size of the block
49# m.id # get identifier of the block
50# m.@ # the same as m.get
51# ```
52# Here the void attribute in the scope object is memory-block object which provides API to write
53# and read data to the memory.
