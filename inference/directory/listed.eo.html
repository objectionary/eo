1# Names of everything the directory holds directly, ordered by their bytes.
2# It is a method of `directory`, taken off the directory it lists, and it
3# answers with a `tuple` of names and not of paths: what stands before them
4# is the directory itself.
5#
6# The stream is walked the way C walks it, one entry at a time, and it is
7# closed before the names are handed over. Posix opens it with `opendir` and
8# reads it with `readdir`; Windows opens a search over the directory and a
9# trailing wildcard with `FindFirstFileW`, which reports the first entry
10# along with the handle it hands back, and reads the rest with
11# `FindNextFileW`. Both report `.` and `..`, which name the directory itself
12# and its parent rather than anything inside it, and both are dropped here.
13#
14# The order is the one the bytes of the names give and not the one the
15# filesystem happens to keep, which is arbitrary and differs from machine to
16# machine. The names are sorted by insertion, which costs a comparison for
17# every pair of them in the worst case: this object is for the directories a
18# program walks and not for the ones holding thousands of entries.
