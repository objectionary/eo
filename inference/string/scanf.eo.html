1# Reads formatted input from a string. It is a method of the formatter
2# string (e.g. "Hello, %s!"), with one free attribute `read`, the string
3# where the data exists (e.g. "Hello, John!"). It returns a
4# `org.eolang.tuple` of formatted values (e.g. * "John").
5# Supported formatters are:
6# - %d - parse as integer and convert to `number`
7# - %f - parse as float and convert to `number`
8# - %s - parse as string and convert to `string`.
9# A space in the format matches a run of one or more spaces in the input, so
10# extra spaces between fields never shift or drop the values that follow.
11#
12# The `%f` conversion never materializes the whole power of ten at once,
13# because `10.power 309` is already infinity: a single multiplication by it
14# turns every mantissa into infinity and a single division by it turns every
15# mantissa into zero, whatever the written value is. `raised` and `lowered`
16# therefore scale in steps of at most `10^200`, so every intermediate stays
17# inside the double range and an underflow happens only when the value itself
18# underflows. Both stop as soon as the value is zero or infinite, since no
19# further step can move it, and that is what keeps the recursion short for an
20# exponent written far outside the range, such as `1e999999999`. The step was
21# `10^300` until #7456: `number.power`'s exponentiation by squaring drifts
22# further from the exact power of ten the larger the exponent it is asked
23# for, and at 300 that drift was already enough to carry a text naming a
24# value inside the double range past its edge into infinity; 200 keeps the
25# same one-step shape for every exponent this parser is ever asked to
26# handle while landing on a smaller power of ten to start the drift from.
