1# Takes a piece of the string as another string, counting characters and not
2# bytes. Here `start` must be a non-negative integer index to start slicing
3# from, while `len` must be a non-negative integer amount of characters to
4# take. A fractional, `nan` or infinite `start` or `len` terminates the
5# computation immediately. Both of them walk the UTF-8 sequence character by
6# character, so a multi-byte character counts as one. An index outside the
7# bounds of the string terminates the computation. Every multi-byte sequence is
8# validated against the UTF-8 rules of the Unicode standard (Table 3-7), the
9# same way `length` does: each following byte must be a `10xxxxxx` continuation
10# byte, and the second byte is range-checked so that overlong encodings
11# (`C0`/`C1` leads, `E0` with an `80`-`9F` second byte, `F0` with an `80`-`8F`
12# second byte), UTF-16 surrogates (`ED` with an `A0`-`BF` second byte) and code
13# points above U+10FFFF (`F4` with a `90`-`BF` second byte, and `F5`-`FF` leads)
14# are rejected. A malformed sequence terminates the computation, exactly like a
15# truncated character does.
