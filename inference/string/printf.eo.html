1# Object `printf` allows you to format and output text depending
2# on the arguments passed to it and return it as `org.eolang.string`.
3#
4# A specifier reads as `%[N$][flags][width][.precision]conversion`, where
5# `N$` picks the `N`-th argument (1-based) instead of the next sequential
6# one, `-` justifies to the left, `0` pads a number with leading zeros,
7# `width` is the minimum count of characters and `.precision` truncates
8# the text (or, for `%f`, counts the fraction digits).
9#
10# When arguments are processed - they're dataized and converted to objects
11# depending on next flags:
12# - %s - converts object to `string`
13# - %d - converts object to `int`
14# - %f - converts object to `float`
15# - %x - converts object to `bytes`
16# - %b - converts object to boolean, `true` or `false`.
17#
18# The format is walked over its bytes, and not over its characters, because
19# `%` never occurs inside a UTF-8 multi-byte sequence, so a literal byte is
20# copied through untouched and the walk stays linear in allocation.
21#
22# The work is done by two objects calling each other, so that the format is
23# traversed exactly once: `walk` copies a literal byte and steps forward,
24# handing every `%` to `spec`, which reads one specifier and asks `walk` to
25# continue after it.
26#
27# `spec` reads that specifier from left to right and names every position it
28# stops at: `dollar` is the `$` of a positional argument, `flags` opens
29# the specifier itself, `digits` follows the `-` and `0` flags, `dot`
30# follows the width digits, and `end` holds the conversion letter. Those
31# positions, and everything derived from them, are memoized, because the
32# language caches through `!` alone, and they are listed alphabetically
33# rather than in reading order, because the linter sorts them by name.
34#
35# The `%s` conversion refuses an argument whose bytes do not decode as UTF-8.
36# `false` and `true` dataize to the single bytes `00-` and `01-`, which are
37# also the valid one-character encodings of U+0000 and U+0001, so an object
38# knows its own bytes here and not its type: a boolean routed through `%s`
39# is printed as that control character instead of being rejected, and `%b`
40# remains the conversion to reach for a boolean.
41#
42# The `%b` conversion refuses an argument whose bytes are neither `00-` nor
43# `01-`, so a text or a number reaching it terminates instead of being
44# printed as `false`. The coin lands the other way up as well: the
45# one-character texts of U+0000 and U+0001 are accepted as booleans, since
46# their bytes are the bytes of `false` and `true`.
47#
48# The `%d` guard names the number it rejects through `as-scientific` and not
49# through `%f`, because every magnitude it rejects is past the range `as-fixed`
50# writes, and a reason rendered with `%f` destroyed itself instead of arriving.
51#
52# The `%f` conversion leaves the `cant-print` fallback of `as-fixed` unbound,
53# so a number it refuses, a non-finite one or a magnitude of 2^63 or larger,
54# terminates with the reason `as-fixed` gives, instead of that reason standing
55# in the text where the number was meant to be. Its tests recover from that
56# termination instead of declaring it with `-->`, because a returned text of
57# more than one byte fails to dataize as a boolean exactly as a termination
58# does, and a `-->` test would pass either way.
