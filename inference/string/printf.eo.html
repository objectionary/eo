1# Object `printf` allows you to format and output text depending
2# on the arguments passed to it and return it as `string`.
3#
4# A specifier reads as `%[N$][flags][width][.precision]conversion`, where
5# `N$` picks the `N`-th argument (1-based) instead of the next sequential
6# one, `-` justifies to the left, `0` pads a number with leading zeros,
7# `width` is the minimum count of characters and `.precision` truncates
8# the text (or, for `%f`, counts the fraction digits).
9#
10# When arguments are processed - they're dataized and converted to objects
11# depending on next flags:
12# - %s - converts object to `string`
13# - %d - converts object to `int`
14# - %f - converts object to `float`
15# - %x - converts object to `bytes`
16# - %b - converts object to boolean, `true` or `false`.
17#
18# The format is walked over its bytes, and not over its characters, because
19# `%` never occurs inside a UTF-8 multi-byte sequence, so a literal byte is
20# copied through untouched and the walk stays linear in allocation.
21#
22# The work is done by two objects calling each other, so that the format is
23# traversed exactly once: `walk` copies a literal byte and steps forward,
24# handing every `%` to `spec`, which reads one specifier and asks `walk` to
25# continue after it.
26#
27# `spec` reads that specifier from left to right and names every position it
28# stops at: `dollar` is the `$` of a positional argument, `flags` opens
29# the specifier itself, `digits` follows the `-` and `0` flags, `dot`
30# follows the width digits, and `end` holds the conversion letter. Those
31# positions, and everything derived from them, are memoized, because the
32# language caches through `!` alone, and they are listed alphabetically
33# rather than in reading order, because the linter sorts them by name.
34#
35# The `%s` conversion refuses an argument whose bytes do not decode as UTF-8.
36# `false` dataizes to the single byte `00-`, which is also the valid
37# one-character encoding of U+0000, so an object knows its own bytes here
38# and not its type: FALSE routed through `%s` is printed as that control
39# character instead of being rejected. TRUE dataizes to `FF-`, which no
40# text encodes, so it is rejected. `%b` remains the conversion to reach
41# for a boolean either way.
42#
43# A number gets no better answer from `%s`: its bytes are printed as text
44# when they decode as UTF-8, and refused when they do not, so the outcome
45# depends on the value. `42` prints as `@E` and six NUL characters, while `1`
46# terminates. `%d` and `%f` are the conversions to reach for a number.
47#
48# The `%b` conversion refuses an argument whose bytes are neither `00-` nor
49# `FF-`, so a text or a number reaching it terminates instead of being
50# printed as `false`. The coin lands the other way up as well: the
51# one-character text of U+0000 is accepted as a boolean, since its byte is
52# the byte of `false`.
53#
54# The `%d` and `%f` conversions refuse an argument whose bytes are not eight
55# wide, naming the argument and the conversion the way `%b` does. Without that
56# guard the bytes were read as a number anyway and whatever met them answered
57# for itself: `%d` came back naming the receiver of the comparison it fell
58# into (#9036), and `%f` called a text a non-finite number, naming what the
59# reading made of the argument instead of the argument (#9037). Eight bytes
60# is as far as the check reaches, since the bytes of a number are the bytes
61# of any other object of the same length, so a text of eight bytes is still
62# written as the number they spell.
63#
64# The `%d` guard names the number it rejects through `as-scientific` and not
65# through `%f`, because every magnitude it rejects is past the range `as-fixed`
66# writes, and a reason rendered with `%f` destroyed itself instead of arriving.
67#
68# The `%f` conversion leaves the `cant-print` fallback of `as-fixed` unbound,
69# so a number it refuses, a non-finite one or a magnitude of 2^63 or larger,
70# terminates with the reason `as-fixed` gives, instead of that reason standing
71# in the text where the number was meant to be. Its tests recover from that
72# termination instead of declaring it with `-->`, because a returned text of
73# more than one byte fails to dataize as a boolean exactly as a termination
74# does, and a `-->` test would pass either way.
