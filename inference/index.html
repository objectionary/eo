copy
The engine answers an object once in every copy of the object around it, so a mark says what the object is in how many copies.
name
The object an answer is copied from, like Φ.number. A formation with no name of its own counts as one name per shape: its voids and what its @ gives, then a line per attribute it binds, with the attribute's own voids and what it gives, like [∅] → Φ.string.
→ and ↺
In a shape, → is what an @ gives, and ↺ is the object the shape is of: [^] → Φ.bytes with a line [^ ∅] > read ↺ is an object of bytes whose read gives the object back.
error
The copy gives T.
unknown
The engine can't name what the copy gives, and says which of four kinds of unknown it is. Filled by nobody: a void of a copy a call made that left it empty; a read of it gives T. Nobody calls this object: a void of a copy that stands for a caller who is not there; what is read off it or handed on from it is that unknown too. Filled by an atom: a void of an object an atom returned, since Java fills that object; it carries on the same way. Nothing ever answers: a read in a loop where nothing ever answers, and what is read off it.
gap
An error or an unknown.
