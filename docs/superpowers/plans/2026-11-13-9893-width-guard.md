# One width guard for `number` (#9893)

**Spec:** `docs/superpowers/specs/2026-11-13-9893-width-guard-design.md`.

## Global Constraints

- `checked` lives in `eo-runtime/src/main/eo/number/checked.eo` as `[^num] > checked`, one `if.` of three branches: `num.as-bytes.size.eq 8` → `number num.as-bytes`; else `T "A number needs exactly 8 bytes, got %d".printf * num.as-bytes.size`. No second message in the five objects.
- Holders stay bound: `sqrt` `num.checked >> arg`, `ln` `num.checked >> n`, `as-char` `num.checked >> arg`, `power` `b.checked >> expo`, `mod` `b.checked >> divisor` and `num.checked >> dividend` — a bare dispatch would blame `lt`'s own `b` (#9283).
- Untouched: `is-finite`, `is-nan`, `eq`, the atoms' `Numeric` message, `power`'s receiver.
- Tests are `++>` / `-->` inside `checked.eo` (`CLAUDE.md` forbids Java tests for an EO object); layout is whatever the `format` goal of `eo:compile` produces.
- Green: `mvn -Pqulice -pl eo-runtime verify`.

## Review Focus

1. A wrong-width receiver of `sqrt`, `ln`, `power`, `as-char` terminates with the one message — `checked.eo` `stops-on-a-number-that-is-not-eight-bytes`.
2. A wrong-width receiver of `mod` terminates only on the path that subtracts; the zero-divisor, nan and infinity answers return it as it stands — `mod.eo` `can-return-nan-when-the-dividend-is-nan`.
3. A wrong-width divisor of `mod` and `power` terminates at the first `if.` condition, not in `cant-mod` — no EO test can read a message, so `git grep -n "must be a number"` empty plus the reviewer reading `mod.eo`.
4. An eight-byte value is untouched, infinities, nan and `-0` included — `checked.eo` `can-return-a-number-of-eight-bytes`, `sqrt.eo` `can-take-a-square-root-of-negative-zero-preserving-sign`.
5. `mod`'s arithmetic and `as-char`'s range message do not change — `mod.eo` `can-take-a-modulo-of-*`, `as-char.eo` `stops-on-a-code-past-the-ascii-range`.
