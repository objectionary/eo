eo:transpile

Full name:

org.eolang:eo-maven-plugin:0.63.5:transpile

Description:

Transpile.

This Maven Mojo transpiles XMIR files into Java source files. The goal of this class is to automate the process of transforming EO intermediate representations (XMIRs) into Java code, optimize the output, and integrate the results into the Maven build lifecycle for further processing.

This is one of the final goals that transpiles XMIRs to Java files generated by MjAssemble, MjParse or MjPull goals. The resulting Java files are stored in a directory Seqdir numbers "transpile". The intermediate optimized XMIRs are stored in a directory Seqdir numbers "pre-transpile".

Before anything is written, the members of every package this build compiles an object for are put inside that object, the way MjMerge does it. The two are the same step and running both changes nothing, since Merging leaves a merged member alone; it is done here as well because the shape of an object decides the name of the Java class of every atom it holds, and a build that skipped the goal would name classes that the library it compiles against does not carry. An atom string.foo.bar ships as EOstring$EOfoo$EObar, which is where it lands once foo is an attribute of string, and nowhere near the org.eolang.EO_string package an unmerged +package string would compile it into (#8295).

Attributes:

  • Requires a Maven project to be executed.
  • Requires dependency resolution of artifacts in scope: compile.
  • The goal is thread-safe and supports parallel builds.
  • Since version: 0.1.
  • Binds by default to the lifecycle phase: process-sources.

<coverage> boolean - Whether to wrap every located object in the generated Java into PhCoverage, so it records a coverage hit the first time it is touched at runtime. Off by default, so a production build stays lean. The hits are appended to the file named by the eo.coverageFile system property of the JVM that runs the compiled program; when that property is absent, every hit is a silent no-op. In eo-runtime the coverage profile turns this on and forwards that property to surefire in one step (see its pom.xml). The measure Maven goal (MjMeasure ) turns the raw hits into an LCOV tracefile, bound to the verify phase since the hits only exist after tests actually run. eo-runtime pairs it with measure.minimum on that same goal, failing the build when the covered percentage of dataized .eo objects drops below a threshold, mirroring how the jacoco profile binds a check goal with its own per-metric thresholds.
User Property: eo.transpile.coverage
Alias: transpile.coverage
<deadline> long - How many seconds a single test made of an ++> or --> attribute may run before it is stopped and reported as skipped. The number is written into the @Timeout of every test, so the tests keep it in any build that compiles them, even one that configures nothing for JUnit. A test that outlives it is reported as skipped by org.eolang.Deadline, rather than left to run until the heap of the whole build is gone. Zero means no deadline, and no @Timeout is written; a negative number is refused. The property has the same name as the one eo-runtime gives its own tests, so one setting covers both.
Default: 1
User Property: eo.transpile.deadline
Alias: transpile.deadline
<keepBinaries> Set<String> 0.24 List of inclusion GLOB filters for unplacing and unspiling (ONLY these files will stay).
See also: Placing and Unplacing in JAR Artifacts
<located> boolean - Whether to wrap every dispatched object with a location-carrying PhSafe, so a panic reports its .eo source position. Off by default, so a production build stays lean; turn it on (as eo-runtime does for its tests) to keep precise .eo locations in panics.

User Property: eo.scope
<skip> boolean - Whether we should skip goal execution.
Default: false
User Property: eo.skip
<skipBinaries> Set<String> 0.15 List of exclusion GLOB filters for finding class files while placing them from where they were resolved to classed directory.
<skipProgramLints> Set<String> 0.57 List of WPA lints which must be skipped during the linting.
<skipSourceLints> Set<String> 0.57 List of individual lints which must be skipped during the linting.
<superclass> String - The class that a generated class extends instead of PhDefault, set through eo.transpile.superclass. A tool that needs control over the objects of a program can name its own subclass of PhDefault here and see every add() and take() the program makes. The name is written into the generated Java verbatim, so a class outside org.eolang has to be named in full, since the generated files import nothing but org.eolang.*.

The substitution reaches every class the generated Java declares with an extends clause of its own, and every object it builds with new: the context of a generated apply(), an anonymous abstract object, and the argument of a PhApplication. An object with a @base extends PhOnce instead, and keeps doing so: PhOnce is a decorator, and the object it wraps is itself substituted, so nothing is lost.

Since the generated Java builds objects with new, the named class has to offer the same constructors PhDefault does where the transpiler calls them: the one taking nothing, the one taking a location String, and the one taking a byte[]. A class that leaves one out fails to compile in generated sources.


Default: PhDefault
User Property: eo.transpile.superclass
Alias: transpile.superclass
<tables> File - The directory with the tables that MjInfer writes, read by purify.xsl to find out which formations are safe to cache. The default is the one MjInfer saves them to, so a build that runs the goals in their usual order needs to say nothing here. A build that skips eo:infer leaves the directory absent, and then nothing is marked. Falls back to a directory Seqdir numbers "inference" when unset.
User Property: eo.transpile.tables
Alias: transpile.tables
<tests> boolean - Whether to transpile tests.
Default: true
User Property: eo.transpile.tests
Alias: transpile.tests
<timeout> Integer 0.28.12 Mojo execution timeout in seconds.

Four hours, which no goal of this plugin has ever needed and a goal that never returns will always exceed, so Deadline does what its javadoc says it does without a build having to configure anything. The default used to be Integer.MAX_VALUE, about sixty eight years, which meant the deadline never fired and the thread and the java.util.concurrent.FutureTask behind it were started for nothing. A build whose goals legitimately take longer raises it through eo.timeout, and one that wants no deadline at all sets it to zero.


User Property: eo.timeout
<uncached> boolean 0.55.0 Bypass the global cache, if TRUE.
Default: false
User Property: eo.cache.bypass
Alias: cache.bypass
<unroll> boolean 0.29.0 If set to TRUE, the exception on exit will be printed in details to the log.
User Property: eo.unroll
Alias: unroll
